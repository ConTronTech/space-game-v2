DESIGN:
1. New module package/modules/combat/weapons/ (name "combat/weapons"; requires core/input_handler; optional ship/ship_core, core/render_engine, world/asteroids, world/star_system, world/stations, fx/particles (via the event only), core/audio, ship/docking, ship/warp_drive). Weapons are DATA (data/weapons.json through core::IData, built-in defaults if missing) plus a small class per behaviour kind: kind "projectile" (blaster) and kind "beam" (mining beam). Adding a weapon later = a JSON entry (+ a class only for a new behaviour). Fields: name, kind, damage, speed (projectile m/s, default ~600 so it is clearly faster than the ship but not instant), lifetime, range (beam), rate_of_fire, heat_per_shot / heat_per_second, cooldown_rate, overheat_lockout_seconds, recoil (impulse, m/s of ship speed per shot for a nominal ship mass), spread, muzzle offset in the ship frame, colour, beam_dps (damage per second on asteroids).
2. Input (config/input/default.json + docs/INPUT.md + docs/QUICKSTART.md): `fire` = mouse left button (hold to keep firing at the rate of fire), `weapon_1` / `weapon_2` = keys 1 / 2 (select blaster / mining beam), `weapon_next` = key X? NO: X is brake; use keys 1/2 only plus mouse wheel if the input layer supports it (check; skip if not). Firing is ignored while paused, dead, warping, docked/docking (ship::IDocking::docked or the held ship), or while the mouse is not captured (free mouse mode = menu clicks must NOT shoot; check how core/input_handler exposes capture state; if it does not, use the same condition the ship uses for mouse look and say so).
3. BLASTER (projectile): a pool of at most `combat.max_projectiles` (default 128, Low preset 64) bolts, struct-of-arrays, NO allocation after init. Each bolt: position (double), velocity = ship velocity + muzzle direction (ship forward with a small seeded spread) * speed, lifetime, damage. Each fixed step advance and SWEEP the segment [old,new] against: asteroids (world::IAsteroids::nearest + a cheap spatial prefilter: only test asteroids within the bolt's step range plus its radius; nearest() is O(count) and must NOT be called per bolt per step: query once per fixed step per ~N bolts or maintain a small cache of asteroids near the ship (e.g. within 3000 units, refreshed at 4 Hz like the radar does) and also test the sun/planets/moons (IStarSystem bodies as spheres) and stations (IStations, sphere of half extent). On hit: apply damage (asteroids: see 5; bodies/stations: no damage, just impact effect), emit fx::SpawnParticles "spark" at the hit point, remove the bolt, and emit a `combat::ProjectileHit { targetKind ("asteroid","planet","moon","sun","station"), id, position, damage, shooter }` event so future NPC/ship damage can subscribe. Drawing: one render pass, all live bolts as short additive line segments or tiny quads in ONE glDrawArrays (camera-relative double->float), depth test on / write off, GL state restored; muzzle flash via SpawnParticles "muzzle".
4. MINING BEAM (beam): while `fire` is held with the beam selected: a ray from the muzzle along the ship forward, `range` units (default 500), finds the nearest asteroid it intersects (sphere test against the cached nearby asteroids), applies beam_dps * dt damage to it, draws a thin additive line/quad from muzzle to hit point (or full range if nothing), spawns "spark"/"debris" particles at the contact at a modest rate, and adds heat per second. Beams do NOT hit planets/stations (they just show the beam to max range).
5. ASTEROID HEALTH (small, contained addition to world/asteroids): asteroids gain hit points = k * radius^2 (tunable asteroids.hp_scale default so a radius-9 rock takes a few seconds of beam or ~10 blaster bolts; document), and IAsteroids gets NON-PURE extensions with safe defaults: `virtual bool alive(int i) const { return true; }`, `virtual bool damage(int i, float amount, Vec3d hitPos) { return false; }` (returns true when this call destroyed it). world/asteroids implements them: a destroyed asteroid is removed from drawing, from the physics pool and from nearest() results (radar), emits `world::AsteroidDestroyed { id, position, radius, ore }` (in asteroids_api.h; this is what 4.3 mining will turn into ore drops), and a debris burst via fx. Destroyed state is NOT saved yet (documented: the field regenerates on load; 4.3 will save it).
6. HEAT: each weapon has a heat value 0..1 (state per weapon, shared clock): rises per shot / per second firing, cools at cooldown_rate; at 1.0 the weapon locks out for overheat_lockout_seconds (cannot fire). Recoil: each blaster shot applies -direction * recoil to the ship's velocity through IShip::setVelocity (Newtonian, tunable combat.recoil_scale default 1, 0 disables; mention the ship has no mass model yet). Provide ship-side info to the HUD via a service `combat::ICombat { selected(); weaponName(i); heat(i); overheated(i); firing(); hitMarkerAge() }` in weapons_api.h and events `combat::WeaponChanged`, `combat::Overheated` (the HUD worker will show a crosshair heat bar later: do NOT edit the HUD now).
7. Audio (optional): if core/audio has a sound ("laser" / "blaster" / "impact") use it via the existing API, else skip silently.
8. Quality: add rows to core/quality/quality_rules.h (minimal): combat.max_projectiles (low 64, medium 128, high 192, ultra 256), combat.beam_particles (rate multiplier). Dev flags: --auto-fire=FRAME,FRAMES (hold fire for a span), --auto-weapon=N for scripted scenarios.
9. PURE LOGIC + TESTS in weapons_rules.h (no GL/SDL/engine types), tolerances, no exact float equality: bolt step + inherited velocity, swept segment-vs-sphere (including a fast bolt that would tunnel, a tangent miss, start inside a sphere), beam ray vs sphere nearest, heat/cooldown/lockout state machine (fire rate limiting, overheat and recovery), asteroid hp and damage to destroyed transitions, pool capacity (drop on full, slot reuse), data parsing with defaults. Add the asteroid damage tests to test_asteroids.cpp.
