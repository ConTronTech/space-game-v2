DESIGN:
1. gameplay/inventory (new module, name "gameplay/inventory"; requires core/data_registry (optional: built-in tiny defaults if data missing); optional core/save_system). Pure logic in inventory_rules.h (no GL/SDL/engine types): a cargo hold with a capacity in CARGO UNITS (tunable inventory.capacity default 100; later upgradable: expose setCapacity/capacity like IWarpDrive levels: a `capacity_level` table in data/cargo.json with 4 invented levels 100/200/400/800), stacks keyed by item id (ores from data/ores.json and items from data/items.json share one namespace; ore volume 1 unit per ore unit, items from an optional "volume" field default 1), add (returns how much was accepted, never exceeds capacity, partial accept), remove (fails atomically if not enough), count, total used, free, list in a stable order; unit tests (tolerances, edge cases: zero/negative amounts, overflow, atomic remove, unknown ids allowed as raw stacks). Service `gameplay::IInventory { capacity(); used(); free(); count(id); add(id, amount) -> accepted; remove(id, amount) -> bool; stacks(vector<Stack>&); }` in inventory_api.h, events `gameplay::InventoryChanged{id, delta}` and `gameplay::CargoFull{id, refused}`. ISaveable id "gameplay/inventory" (stacks + capacity level; missing = empty). Dev flag `--give=iron:50,copper:20` for testing (documented as test-only) and `--clear-cargo`.
2. gameplay/mining (new module "gameplay/mining"; optional deps: world/asteroids, gameplay/inventory, ship/ship_core, fx/particles, core/physics_world not needed). On world::AsteroidDestroyed{id, position, radius, ore}: spawn ORE CHUNKS: N chunks (tunable mining.chunk_count_scale; total ore amount = mining.yield_scale * radius^2 in ore units, e.g. a radius-9 rock ~ 40 units, a radius-3 rock ~ 4; rounded, at least 1) that fly outward from the destruction point with a small seeded random velocity plus the asteroid velocity (0, asteroids are static) and drift forever Newtonian (no drag; despawn after mining.chunk_lifetime seconds default 300 or when far from the ship > mining.chunk_range 3000 units). Chunks are a small pooled array (mining.max_chunks default 96, Low 48; oldest evicted), each with ore id and amount, drawn in ONE glDrawArrays as small camera-facing coloured quads/points (ore colour from data/ores.json) in a pass ordered after asteroids. PICKUP: within mining.scoop_radius (default 12 units) of the ship AND relative speed below mining.scoop_speed (default 40 m/s): the chunk is collected into the inventory (partial if the hold is nearly full: leave the remainder in the chunk; CargoFull event when refused) with a small "pickup" particle/sound (fx.SpawnParticles "spark" small count; audio if a sound exists). Fast fly-through does not collect (hard: you must slow down and match). Ship velocity/position read through ship::IShip per use (optional). Save chunks? NO (documented: chunks are lost on load; destroyed asteroids are not saved yet either: mention in docs as a known gap for a later persistence step).
   Also emit `gameplay::OreMined{ore, amount}` when collected (for HUD/toasts/stats later).
3. Ore variety comes from the asteroid's own ore id (world::IAsteroids::ore(i), already tinted by data/ores.json rarity): unknown/"rock" ore yields the id "rock" (worthless filler: still occupies cargo: fine).
