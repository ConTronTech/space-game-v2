DESIGN:
1. New module package/modules/fx/particles/ (name "fx/particles"; requires core/render_engine; optional ship/ship_core, core/physics_world, ship/warp_drive, world/star_system). A typed event API in particles_api.h: `fx::SpawnParticles { kind, position (double or camera-relative float: choose double world position), velocity, count, colour, size, lifetime }` emitted through eng.events by any module (this is how later weapons/mining spawn effects), plus named presets ("exhaust", "spark", "debris", "warp_flash", "muzzle") in data-driven form: data/particles.json (name, count range, speed range, lifetime range, size, colour ramp start/end, drag, gravity 0, additive yes/no), read through core::IData with built-in defaults if missing. Pure logic in particles_rules.h (no GL/SDL/engine types): pool (fixed capacity, ring/free-list, NO heap allocation after init), spawn with a seeded RNG, per-step update (velocity, drag, age, colour/size ramp, kill), camera-relative conversion, LOD/budget (drop spawns beyond capacity, distance culling and a per-frame spawn budget), unit-tested with tolerances.
2. Sources (all through the event bus / read-only services, do NOT edit ship_core/warp_drive): engine exhaust: a small stream from the ship's rear while thrust is applied (derive from ship::IShip velocity change / the input action values `thrust` / `strafe` / `lift` via core::IInput: exhaust direction opposite to acceleration, position = ship position + rear offset in the ship frame from core::ITransformSource pose), only visible in chase view (in cockpit view the camera is at the ship: cull particles behind the near plane; do not draw when they'd be within 1.5 units of the camera); hit sparks and debris on core::Collided (posA/posB, normal, speed: count scales with speed) and on ship::DamageTaken; warp flash on warp engage (subscribe to ship::IWarpDrive engaged changes: poll per fixed step, no contract change) and a short streak trail at high speed is NOT needed (starfield does it).
3. Rendering: one render pass ("fx/particles", ordered after the star system/asteroids and before the cockpit), camera-relative, ONE glDrawArrays(GL_QUADS or GL_POINTS with per-vertex size not available in GL2.1 fixed function: use camera-facing quads built into a preallocated vertex array each frame), additive blending only for glow presets, depth test ON with depth write OFF, no lighting, no texture (or one tiny shared soft-dot texture <= 32x32 if you can show it is not slower on llvmpipe), restore all GL state. Cost target: 2000 live particles cost < 0.5 ms CPU on the dev machine; report it and the GPU cost estimate via llvmpipe (2 pinned cores: `taskset -c 0,1 env LIBGL_ALWAYS_SOFTWARE=1`, small --frames, do NOT run it long on the desktop).
4. Tunables (eng.config.get, documented) and preset rows in core/quality/quality_rules.h (one row each, minimal): fx.enabled, fx.max_particles (low 300, medium 800, high 1500, ultra 3000), fx.exhaust (bool, low 1 but half count), fx.spawn_budget per frame, fx.size_scale. Debug flag --fx-test=FRAME spawning a burst in front of the camera for screenshots.
5. Docs: docs/FX.md (new: event API, presets file format, how to add an effect, budgets), docs/MODULES.md, docs/QUALITY.md row.
